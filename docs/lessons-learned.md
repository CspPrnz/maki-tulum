| Date       | Issue                                                                                                                                                                                            | Root cause                                                                                                                                                                                                                                                                                                                                                                                                                                                | Preventive measure                                                                                                                                                                                                                                                                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-07-31 | CI failed on the first real run with `database "maki" does not exist`, after `pnpm verify` was green locally — the third false-green of the same session, one layer deeper than the previous two | Two compounding causes. Turbo 2 runs tasks in **strict env mode**, so `DATABASE_URL` was stripped before reaching vitest (the `test` task declared no `env`/`passThroughEnv`). The repository tests then papered over it with `process.env['DATABASE_URL'] ??= 'postgres://…/maki'` — a database that exists and is migrated on a dev machine but not on CI. The fallback converted a missing-config error into a silent connection to the wrong database | Declare every env var a turbo task needs in `env`/`passThroughEnv`. Never let a test invent a connection string: require the var and throw. `services/api/src/db/index.ts` now throws instead of letting `pg` default to a database named after the OS user, so this fails identically everywhere. Verified both directions — unset ⇒ loud failure, set ⇒ green |
| 2026-07-31 | `pnpm verify` passed locally while CI could not possibly pass: the repository tests query real tables and nothing applied the migration to CI's fresh service container                          | The local dev database had been migrated by hand during development, so the suite was green against pre-existing state. The gate mirrored CI in _steps_ but not in _starting conditions_                                                                                                                                                                                                                                                                  | A verification gate must be run against a **pristine** environment before you claim it mirrors CI. Added `db:migrate` to both the CI workflow and `pnpm verify`; proved it by creating an empty database, reproducing the 10 failures, then re-running green                                                                                                    |
| 2026-07-31 | `/readyz` crashed the API instead of reporting 503 — stopping Postgres killed the process, which on Railway is a restart loop rather than a recoverable outage                                   | `pg.Pool` re-emits idle-client errors on the pool object; an unhandled `'error'` event terminates Node. Neither the health pool nor `db/index.ts` registered a listener. Every readiness test injected fakes, so the production wiring had zero coverage and the crash shipped green                                                                                                                                                                      | Register an `'error'` handler on every long-lived pg/ioredis client. More generally: if a module exports a `defaultXDeps()` used only in production, it needs at least one test that exercises _it_, not just the injected fake                                                                                                                                 |
| 2026-07-31 | Production CORS could be made to reflect any origin with `credentials: true` by a one-line misconfiguration                                                                                      | The allowlist fell back to `(o) => o ?? '*'` when empty, and the production filter that strips localhost could itself empty a localhost-only allowlist — so the guard meant to harden production turned it into allow-all                                                                                                                                                                                                                                 | Fail closed: refuse to boot when the allowlist is empty outside local. A permissive fallback in a security control is a bug even when the "normal" path is correct                                                                                                                                                                                              |
| 2026-07-31 | The rate limiter keyed buckets on the leftmost `X-Forwarded-For` value, which the client writes                                                                                                  | Proxies _append_ the peer address, so the leftmost hop is attacker-controlled; a fresh header value per request minted a fresh bucket and defeated the limiter entirely                                                                                                                                                                                                                                                                                   | Take the rightmost XFF entry, never the leftmost, and unit-test the parser against spoofed prefixes. Any control keyed on a request header needs an explicit note on who can write that header                                                                                                                                                                  |
| 2026-07-31 | Wiring Sentry as delivered would have made it the stack's first processor of guest PII, days after we wrote a document saying not to                                                             | Sentry attaches IPs and request context by default, and `beforeSend` field-deletion does not touch breadcrumbs — and `@sentry/node` v8 turns every `console.*` into a breadcrumb, including the `console.error(err)` immediately preceding capture, where a Postgres unique violation carries the offending email in its `detail`                                                                                                                         | Scrub at init (`sendDefaultPii: false`, `beforeBreadcrumb: () => null`, strip query strings) and log error _messages_, never error objects. Test the scrubbing — an untested privacy control is a comment                                                                                                                                                       |
| 2026-07-31 | Renaming a drizzle migration for cosmetic consistency (`0000_init` → `0001_init`) silently overwrote the previous snapshot when the next migration generated                                     | drizzle keys journal entries and snapshot filenames by zero-based `idx`, not by tag. Renaming the tag without renaming the snapshot leaves the chain intact for `migrate` but the next `generate` writes to the same snapshot filename                                                                                                                                                                                                                    | Don't rename generated migration artifacts. If you must, rename the snapshot and journal entry together and verify by migrating a pristine database end to end                                                                                                                                                                                                  |
| 2026-07-31 | CI had **never passed** — all 5 runs on `main` failed, while `TODO.MD` said "CI 🟢 Wired" and `CLAUDE.md` said "CI green on main"                                                                | `pnpm check-env` is CI's first step and exited 1 on two self-inflicted issues: `NEXT_PUBLIC_SITE_URL` was used in `apps/web/app/layout.tsx` but never added to `KNOWN_ENV`, and the script scanned its own source, where the doc comment `process.env.X` registered as a phantom var. Because step 1 failed, format/typecheck/lint/test/build never executed on any run — the pipeline was decorative                                                     | Never record a CI status from the workflow file's existence. Read the actual conclusion (`gh run list`) before writing 🟢 anywhere. `pnpm verify` now runs CI's exact sequence locally so the discrepancy shows up in one command                                                                                                                               |
| 2026-07-31 | The new `pnpm verify` gate was red on a clean checkout the first time it ran (37 files failed `format:check`, 25 pre-existing)                                                                   | Prettier was configured in CI and `package.json` but never actually enforced, because CI died at check-env before reaching it. Unformatted files accumulated on every commit since Phase 0                                                                                                                                                                                                                                                                | A gate wired to a target that is red on baseline is a false-positive machine that gets ignored, then disabled. Run any new gate on a clean tree and drive it green **in the commit that introduces it** — never land a gate you have not watched pass                                                                                                           |
| 2026-05-04 | Vitest fails to resolve `server-only` when testing server modules                                                                                                                                | `server-only` is a Next.js-provided virtual module; vitest runs outside the Next runtime so the package isn't installed                                                                                                                                                                                                                                                                                                                                   | Alias `server-only` to a no-op shim in `vitest.config.ts` (`apps/web/test/server-only-shim.ts`); makes server-only modules unit-testable                                                                                                                                                                                                                        |
| 2026-05-04 | Vite static analyzer rejects ``import(`../locales/${locale}.json`)`` in `@maki/i18n`                                                                                                             | Template-string dynamic imports must start with `./` and stay within one directory; cross-dir paths break the analyzer                                                                                                                                                                                                                                                                                                                                    | Use a static map of pre-imported modules (`const LOCALE_MAP: Record<Locale, Translations> = { en, es, de }`); also gives us static bundling and zero runtime cost                                                                                                                                                                                               |
| 2026-05-04 | Next.js `next build` failed with "Module not found: Can't resolve './components/Container.js'" in `@maki/ui`                                                                                     | Two compounding issues: (1) workspace packages with `"main": "./src/index.ts"` aren't transpiled by Next webpack by default; (2) `.js` re-exports of `.tsx` source aren't auto-resolved                                                                                                                                                                                                                                                                   | Add `transpilePackages: ['@maki/ui', '@maki/i18n', '@maki/types', '@maki/config']` to `next.config.mjs`, and drop `.js` extensions from re-exports inside workspace packages (Bundler resolution makes them optional)                                                                                                                                           |
| 2026-05-04 | `services/api` typecheck error TS6059: "File ... is not under 'rootDir'" after aliasing `@maki/config` to source                                                                                 | When TypeScript follows path/workspace resolution into a sibling package's source files, those files fall outside `rootDir: "./src"` and TS treats it as a project-structure violation                                                                                                                                                                                                                                                                    | Drop `rootDir` from `services/api/tsconfig.json`. `outDir` alone controls build output; without `rootDir`, TS computes the common ancestor and accepts cross-package imports without complaint                                                                                                                                                                  |
| 2026-05-04 | TS7006 "Parameter 'o' implicitly has an 'any' type" in Hono CORS callback                                                                                                                        | Hono's `cors({ origin })` accepts a union including a function, and TS can't infer the param type when the function form is used inside a ternary                                                                                                                                                                                                                                                                                                         | Always type callback params explicitly under `noImplicitAny` — e.g. `(o: string) => o ?? '*'`                                                                                                                                                                                                                                                                   |

## Meta-lessons (about how we built this project itself)

> Sourced from the first Codex red-team pass ([`docs/backlog/plans/codex-red-team.md`](backlog/plans/codex-red-team.md), 2026-07-15) — all 6 proposed meta-lessons reviewed and accepted.

| Date       | Lesson                                                                                                                                                                            | Preventive measure                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 2026-07-15 | A deferred vendor decision is not non-blocking when it defines the domain model (channel manager deferred past the point it shapes the availability schema — MRT-15-P0-02)        | Add a dependency gate requiring vendor proof-of-capability before schema/contract freeze                    |
| 2026-07-15 | An adapter is not evidence that vendors are interchangeable (MRT-15-P0-03)                                                                                                        | Require a capability matrix and sandbox contract suite before promising a vendor swap is low-cost           |
| 2026-07-15 | Privacy decisions must precede data-schema and lifecycle design, not follow it (MRT-15-P0-05)                                                                                     | Require a data map, lawful-basis matrix, and deletion/retention design before any new guest-data collection |
| 2026-07-15 | Accepted ADRs must trigger a repository-wide contradiction check — ADR 0012 (Brevo) shipped while CLAUDE.md and implementation-plan.md still named Postmark/Twilio (MRT-15-P1-04) | Add a checklist/CI doc scan for superseded provider and architecture choices                                |
| 2026-07-15 | Conversion features require an explicit anti-pattern invariant, not just a listed don't (MRT-15-P2-01)                                                                            | Add anti-pattern acceptance checks to every growth/checkout experiment                                      |
| 2026-07-15 | Plans must be reconciled when shipped state changes — implementation-plan.md said "no code yet" after Phase 0/1A had shipped (MRT-15-P2-02)                                       | Make current-state reconciliation a required close-out step for each phase                                  |
